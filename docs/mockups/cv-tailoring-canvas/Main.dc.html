Changes from this brief

  1. A5 toast reads "Couldn't generate. Try again", not "Couldn't generate — try again": app language allows no em dashes, and the error pattern is "what failed. what to do".
  2. The surrounding chrome uses a sample posting (Tidepool, Senior Full-stack Engineer), not a real Job board posting: this canvas cannot read the live database. Swap in a real one at review; nothing in the row depends on which.
  3. Owner, 17 Nov: View tailored CV and Regenerate are one split button inside the gradient border, split by a 1px seam. Regenerate only exists once a tailored CV does, so it never appears in A1, A2 or A5.
  4. A3 draws the Regenerate tooltip open (hover or focus) so its copy is visible on the canvas.
  5. A7 is one 390 artboard holding both A1 and A3. With the row's existing flex-wrap, the title takes the full width and the button group wraps to its own line under it, left aligned; both pairs fit on that one line (A3 is about 300 of 358 px).
  6. Owner, 17 Nov: one pending state for both first run and regenerate. A4 now shows the A2 button (Tailor my CV, spinner, rotating border) instead of a disabled pair with its own spinner; A3 returns once the new CV is ready.

Proposals

  • Gradient border for the CV button (owner request, 17 Nov): a 1.5px multi-hue border in three states. Idle (A1, A5): at 45%, full on hover. Working (A2, A4): the gradient rotates, alongside the spinner, so the state is never colour alone. Ready (A3, A6): full and still. This is a new decorative treatment, not one of the Loots state colours, so it needs a decision log entry and a token or a Button variant before code.
  • ArrowUpRight with a hover nudge on View tailored CV and Apply, matching the job list card's Apply (translate 2px up and right, 200ms ease-out). Already in the app; no new token.
  • Otherwise none: Button, Tooltip, the sonner toaster and LoaderCircle with animate-spin are already in the app.

Open questions

  1. Regenerate fails: does the earlier tailored CV survive? Recommend yes: write the new PDF before replacing the old one, so A5 can fall back to A3 as drawn.
  2. Apply while pending: stays enabled in A2 and A4. Recommend keeping it enabled; tailoring is optional and should never block applying.
  3. Long waits: the spinner is the only feedback. Recommend adding the app's progress pattern as a tooltip on the pending button, "Tailoring CV… ~1 min", if calls routinely take more than 10 seconds.
  4. Leaving the page mid-call: recommend the request keeps running server side and the page shows A3 on return, with the success toast "Tailored CV ready" only if the owner is still on the page.
