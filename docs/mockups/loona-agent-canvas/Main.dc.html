Changes from this brief

  1. Success reply reads "Added Jane to your contacts." instead of "Contact added". The brief keeps Loona's replies as full sentences, and the activity log repeats the chat wording, where "Contact added" alone would not say who. One stored sentence then serves both.
  2. Failure reply: "Couldn't add Jane. 09171234567 is already saved on a contact." Two short sentences instead of a dash: says what failed and why, no em dash.
  3. The second Added row is a placeholder, [SECOND CONTACT]. The brief's only real example is Jane, and docs/product/loona-agent.md is not on main or any branch yet, so there was no second real acceptance example to use. Swap it in at review.
  4. No title row above the tabs. Slice 1's chat page has none (the sidebar's Agents › Loona item names the page), so the Chat / Activity tabs sit at the top of the content column instead of below a title. Adding a title row would change the shell, which the brief keeps out of scope.
  5. Acknowledgement drawn with a full stop, "Got it, adding now.", to match the full-sentence rule.

Proposals

  • --destructive-soft in globals.css, beside --destructive, mirroring --topic-learned-soft: light oklch(0.955 0.03 25), dark oklch(0.3 0.06 22). The Failed chip is text-destructive on it: 5.0:1 light, 5.3:1 dark. --diff-remove-soft is nearly the same colour, but it means "replaced in a diff", so a role-named token reads better.
  • ActivityChip (outcome: success | failure): StatusChip's exact shape (Badge variant="secondary", gap-1, 12px icon) with its own words and icons: Added + CircleCheck on bg-topic-learned-soft text-topic-learned (4.9:1 light, 7.8:1 dark); Failed + CircleX on bg-destructive-soft text-destructive.
  • Pending cue on MessageContent: a 6px muted-foreground dot after the text, opacity 1 → 0.25 → 1 over 1.8s, with screen-reader text "Still working". No new token.
  • ActivityRow grid: chip 76px, summary 1fr, time auto, in a divided panel (gap-px bg-border, as the Jobs scraper panel). At phone width, and in the L8c side panel, the summary drops to its own line under chip and time.

Recommendations

  • Pending cue: (a), the pulsing dot. It is the only option that reads as "still going" without making the message itself look wrong; (b) muted text looks disabled or failed and dims the one line the owner needs to read; (c) a spinner shouts for a run that may take a while.
  • Resolved bubbles stay plain text, no inline success icon. A green check in chat would need a red mark for failure to stay fair, and the brief keeps red out of the transcript. The resolved message is its own new bubble with no dot, which is the difference L3/L4 need from L2.
  • L8: tabs (L8a, L8b). The log repeats what the chat already shows, so a side panel (L8c) puts the same sentence on screen twice and squeezes the chat; it earns its place only once a second agent or a cross-agent feed exists. A separate route adds navigation for one list.

Open questions

  1. Acknowledgement wording: "Got it, adding now." (brief), "Adding Jane now." or "On it." Recommend "Adding Jane now.": shorter, and it names who, so the pending bubble already says what is in flight.
  2. Duplicate-phone wording: "Couldn't add Jane. 09171234567 is already saved on a contact." (drawn) or naming the existing contact, "Couldn't add Jane. 09171234567 is already [EXISTING CONTACT]'s number." Recommend naming the contact when the write knows it, since the owner's next step is to look that contact up.
  3. Row limit: recommend no pagination now. Load the newest 50, and when there are more, end the list with a muted line "Showing the latest 50". Revisit once real volume exists.
  4. L8 placement: tabs, side panel or a separate route. Recommend tabs; see above.
  5. Missing docs: docs/architecture/loona-agent.md and docs/product/loona-agent.md are not on main or any branch, and Slice 1 itself is still on feat/agents-loona-chat-shell. The frames follow the brief's wording for both; check them against the docs once those land.
