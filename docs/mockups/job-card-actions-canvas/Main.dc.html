Changes from this brief

  1. "Tailor" reads "Tailor CV": app language wants a verb and an object on every button, and it is still shorter than the detail page's "Tailor my CV".
  2. Tailor's ready label is "View CV", with the same FileText icon and no arrow: it opens a modal, not a new tab, so the up-right arrow would promise the wrong thing.
  3. The posting is a sample (Tidepool, Senior Full-stack Engineer): this canvas cannot read the live Job board. E5 uses a deliberately long title and company to test overflow. Swap in real postings at review.
  4. Score and ATS are rings, not badges (owner's decision, 19 Nov). Both are the same 40px circle: a muted track, a progress arc whose length is the figure, and the figure centred in Geist Mono 12px ("92", "85%"), with "Match" or "ATS" beside it. They move out of the header to the footer's far left on every card, so the header keeps only Save and the title gets its width back on every screen.

Proposals

One new component: a ScoreRing (40px, value 0 to 100, label). The arc is a conic gradient built from the same five hues as --rainbow-gradient, scaled to the arc so every ring shows the whole rainbow; a mask cuts it to a 4px stroke. No new token. The card actions reuse the shipped rainbow-ring class at Button size sm (32px), the same FileText and Mail icons stroked with the ring's gradient, Dialog, Textarea and the toaster.

The reorganization recommendation (E9)

E1 holds on desktop: with the rings in the footer the title has the full header beside Save, and rings, two actions and Apply fit on one line. Two things do read as crowded once drawn with real content, so I recommend a small restructure rather than a new card:

  • Split the footer by role. Tailor CV and Write cover letter sit together on the left; Apply stays alone on the right as the one primary action. In E1, three right-aligned buttons of near-equal weight compete with Apply.
  • Move pay into the footer, just left of Apply. Today pay sits on its own right-aligned line above the separator; folding it into the footer saves a row on every card, which pays for the new buttons.
  • On phones (E10) the footer wraps to two rows: the rings with Apply at the right, then the AI actions. Pay stays on its own line above the separator, since the first row has no room for it. Labels fit at 390, so no icon-only collapse.

Open questions

  1. Rainbow on figures: until now the rainbow meant "AI action". The rings make it mark data too. Recommend keeping it, since both come from the same matching work, but a neutral arc (foreground colour) is the fallback if the footer reads as too busy beside the ringed buttons.
  2. Icons on the card buttons: recommend keeping FileText and Mail. The rainbow icon is what ties the card action to the detail page's, and it costs about 22px each, which fits.
  3. Explaining the rings: recommend a Tooltip on each, "6 of 7 posting skills in your Profile" for ATS, since a bare percentage does not say what it counts.
  4. No skills on a posting: the spec hides ATS. Recommend only the Match ring shows, still at the far left, so the actions do not shift between cards.
